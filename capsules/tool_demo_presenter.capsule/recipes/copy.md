# 内容与口播

先确定主题与观众为什么要看，再确定任务和镜头。每段实操必须证明主题中的一个具体收益，不能先拼现有素材再补解释。写稿前填明 `{audience}`、`{task}`、`{tool_name}`、`{outcome}`、`{viewer_benefit}`，把全片压成一句“用什么，完成什么，观众能得到什么”。人物、角色形象或成果名称只是案例，不代替主题。

## 写稿顺序

1. 尚未确定开头时，写三个候选：观众熟悉的做法还有什么替代办法、想做却卡住的任务、值得展示的实际成果。已有指定原句时保留原句。选与真实结果最贴合的一句，不强造反常识，不承诺未经证实的效率、收入或零门槛。
2. 第一口让没看过项目的人知道在做什么。可以从“除了 {familiar_method}，还有没有什么办法做 {task}？”切入，但不把这个句式套给所有题材。工具名称、局部参数或制作中的小故障，不能单独代替观众关心的任务。
3. 问题之后紧接实际尝试和成果，再顺着“还想让它做什么 → 试出来怎样 → 哪里不对 → 怎么改 → 改完怎样”往下说。需要教程时，再回到起点讲输入和操作。按内容取舍这些环节，不逐项念成清单。
4. 解释功能时，把功能连接到问题与结果。少用孤立术语，不把“统一风格、加缓动、固定比例”等建议当成完整教程。
5. 结尾交付实际可用的提示词、文件、操作入口或检查方法；不以空泛鼓励、关注请求或夸大变现收尾。

## 对标改写

先逐句看原片开头：观众原来熟悉什么、想做什么、被什么拦住，哪一个成果或问题让人想继续看；再看各句对应的画面如何回答。记录在当前制作笔记中，区分内容结构、视觉形式和声音分别参考了什么。人物加卡片、相似音色或相同切点不能证明内容已经对齐。

提取原片的主题、受众、工具角色、观看收益、因果顺序和证据功能，再换自己的案例、素材和措辞。替换角色不等于改成角色介绍。保留已有效的口播、录屏和卡片形式，镜头数量与时长服务新内容。

## 独立听稿

去掉画面听完整口播，应能复述用什么做什么、关键步骤和最终产物。凡是只能跟随画面说“这是角色、这是表情、这是场景”的句子，改为任务动作或删除。

标题、封面、第一句与交付指向同一主题。按自然短句生成字幕，字幕补充理解，不能替口播补上遗漏的工具、任务或逻辑。

## 每次写稿与改稿的自然表达复审

先查主题、观看收益与证据，再去套话、空泛形容、机械排比和助手口吻。用具体修改及其前后结果说明收益，不强行反转，不编造体验，也不靠口头禅装作自然。保留清楚的步骤与必要限定，顺读终稿后再配音；时长改写也须复审。

尤其检查好开头后面是否突然变成产品介绍：抽象地总结效率、可控性或复用价值，往往打断观众的理解。先说实际做了什么、看到什么，再说下一步为什么这样做。能用一次可见的修改说明的好处，不抢在结果之前列成卖点。允许简短观察和自然反应，但必须来自真实示范；口语词不能代替清楚的主语、动作和因果。
